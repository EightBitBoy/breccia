# Performance after plan 18, 2026-11-26

The same measures as `docs/perf/2026-11-25-baseline.md`, taken again after plan 18's tasks 2 to 6 (code of commit
`d626181`). The bars are the owner's (Q3) and are now in spec §8.

## Machine and commands

- The same machine as the baseline: Intel Core i7-13700H, 32 GB, a laptop on mains power, Windows 11 Pro, Git 2.45.2,
  Node 24, Rust 1.90, release builds; the owner's programs were open (noise as in the baseline).
- Core: `cargo test --release -p breccia-core -- --ignored --nocapture scale::`, run twice (run 1, run 2 below).
- Window: `just perf-scale`, run twice (3 measured launches each; the table gives the median of each run's 3 launches
  as `run 1 / run 2`). Off screen, own config dir and exe; the installed Breccia and the clipboard were not touched.
- Raw output is in the plan's `.superpowers/sdd/` workspace (`task-7-*.txt`, local only).
- Spread: the core's folder-wide measures moved by up to 40 % between the two runs (`folder.open` 1723 / 1284,
  `pages.table` 203 / 122); the baseline's own two runs differed by 10 to 30 %. A verdict of "at the bar" below means
  the two runs lie on both sides of it.

## What moved, by task

- Task 3 (the folder opens inside a window that shows at once): window shows 1794 to about 490 ms (bar 500, at it);
  journal usable 1794 to about 1440 ms, because the open no longer waits for the window's setup and first paint.
- Task 4 (a pull no longer makes typing wait while Git rebases; the rebase hooks are kept): the lock held by a pull
  fell from 703 to 1470 ms to about 380 to 400 ms. Still over 100 ms (point 1c).
- Task 5 (long lists drawn by the rows on screen; rows stay in place on a new commit): archive open 92 to 45 ms,
  archive scroll frame 13.8 to 7.1 ms, Git history show more 508 to about 380 ms. Git history open did not move: its
  time is Git's, not drawing (point 2c).
- Task 6a (prepared move first, retry outside the lock): the worst case, a save just before the lock, 1470 to about
  390 ms, now within its bar 500.
- Task 6b (no folder filter at the repository's top): `git.log` 267 to about 227 ms, never pushed 374 to 249 / 338
  (two runs); the gain is inside the noise.
- Task 6c (own step size of 10 pages for the first build): `index_step` 20.5 to about 10 ms; typing wait p95 20.1 to
  about 10 to 13 ms. The whole build went from 4.7 to about 6.0 s (bar 10 s), the price of the smaller steps.
- Unchanged by design: the `git commit` step (820 to 835 ms), the wait of a search during the first build (#103).
- Noted, not caused by a task: `folder.open`, `folder.tree`, `pages.table` and `graph.get` are slower in this
  session's runs than in the baseline's. The two runs here differ from each other by up to 40 %, so this is the
  machine's load (the same code paths were not changed by plan 18); a quiet-machine run is the way to settle it.

# Safety net Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Breccia safe to keep building on: one running copy per user, recovery after an internal error, a log
file with "Open log folder" in Settings, CI on every push, a test that holds the frontend's types to the core's,
Dependabot with `SECURITY.md` and `CONTRIBUTING.md`, and commands that say whether they change anything.

**Architecture:** CI lands first, so every later task is checked by it. The core gains `Command::kind` and the `log`
facade; the shell gains a size-capped log file, one guarded way into the session that recovers from a panic, and the
single-instance plugin. The frontend gains a small `lib/recovery.ts` (tested) and one Settings entry. A Vitest file
reads the Rust sources as text and fails when the two sides disagree.

**Tech Stack:** Rust 1.90 (core, Tauri 2 shell), `log` 0.4 (already in `Cargo.lock` through Tauri),
`tauri-plugin-single-instance` 2, Svelte 5 + TypeScript, Vitest, Playwright e2e over WebView2, GitHub Actions,
Dependabot.

**Spec:** the audit `docs/audit/2026-11-10/` (`README.md`, `bugs.md` B5 to B7, `program.md` M9, M17, M41, M52, M54,
and `notes.md`, whose rules are invariants here), `docs/spec.md` §2 (anti-goals), §6, §7.12, §9, and this plan's
"Product questions". The audit's line numbers are from commit `4b91b0c`; no product code changed between that commit
and this plan, so they still hold except where "Code against the audit" says otherwise.

## Code against the audit (checked 2026-11-10 at `9cb4093`)

- **T14 / M41, event names:** the shell has ten event constants, not nine: `TRAY_EXIT` (`"tray:exit"`,
  `app/src-tauri/src/lib.rs:696`) is the tenth, and its twin is `app/src/api.ts:90`, outside the range `10` to `50`
  the audit names. The contract test covers all ten.
- **T14 / M41, `Output`:** Rust's `Output` (26 fields, `view.rs:29`) and the TypeScript `Output` (`types.ts:246`)
  have the same 26 keys today. Rust always sends every field (no `skip_serializing_if`); TypeScript marks four as
  optional (`reach?`, `gitLog?`, `archive?`, `day?`). That does not break anything and is left to M42 (follow-up).
- **B6, "a second start with a folder argument":** Breccia takes no command-line argument (`main.rs` calls
  `breccia_lib::run()` only); the startup folder comes from `BRECCIA_FOLDER` or the last folder. A second start
  therefore has nothing to hand over but "show yourself". `just dev` already runs under its own identifier
  (`<identifier>.dev`, `app/scripts/dev.mjs`), and `smoke.mjs`, `screenshots.mjs` and `graph-scale.mjs` all set
  `BRECCIA_CONFIG_DIR`, so skipping the plugin under that variable covers every scripted run.
- **B7:** the audit's fix ("re-open the same folder") would drop edits that are only in memory (a page whose save
  failed, `notes.md`: "Unsaved edits win over the disk"). This plan reopens only when no page is unsaved, and keeps
  the session otherwise (Q2).
- **B7, panic messages:** a panic from slicing a string quotes the string (``… of `héllo` ``), so a raw panic
  message can carry note text. The log writes panic messages with every backtick-quoted span replaced (Task 5).
- **M9, `BRECCIA_TRACE`:** `app/e2e/smoke.mjs` reads the app's stderr and `app/e2e/trace.mjs` parses lines of the
  exact form `trace <kind> <name> wait=…ms run=…ms`. The log must keep writing those lines to stderr unchanged.
- **B5:** confirmed as described; the restore arms are at `session/mod.rs:520`, `533`, `779`, `787`, `793`, and
  `files.changed` restores only when it changed nothing (kept, Task 4).
- **M9:** 21 `eprintln!` calls outside tests, as the audit counts (4 in the core, 17 in the shell).

## Product questions (decided by the owner on 2026-11-10)

The owner answered all nine. Q1 to Q3 and Q5 to Q8 are as recommended. **Q4: its own Settings section
"Troubleshooting" at the end, not a row in About. Q9: monthly, not weekly** (grouping as recommended). The tasks
below carry these answers.

- **Q1. What the user is told and shown after an internal error** (B7). *Decided 2026-11-10: the recommendation.* *Recommended:* one
  notice, "Breccia hit an internal error and reloaded your notes from disk. Everything saved is safe; undo starts
  afresh.", and the journal shows, as after opening a folder. *Alternatives:* (a) the same notice, and the page that
  was shown stays shown (more work: the view has to be reopened by key after the reload); (b) no reload: a notice
  "Breccia hit an internal error. Please restart it." and the app keeps the session as it is. Cost if wrong: one
  string and one function in `lib/recovery.ts`.
- **Q2. An internal error while a page has edits that are not on disk yet** (a failed save). *Decided 2026-11-10: the recommendation.*
  *Recommended:* Breccia does not reload (that would drop those edits); it keeps running as it is and says "Breccia
  hit an internal error. Some changes are not saved yet, so your notes were not reloaded. Copy what you need from the
  'could not be saved' notices, then restart Breccia." *Alternatives:* (a) reload anyway and put each unsaved page's
  text into a notice the user can copy from; (b) reload anyway (loses those edits; not recommended, spec §2). Cost if
  wrong: one branch in `Session::recover`.
- **Q3. Starting Breccia while it already runs** (B6). *Decided 2026-11-10: the recommendation.* *Recommended:* the running Breccia's
  window comes to the front (also when it was closed to the tray); the second start ends quietly. *Alternatives:*
  (a) the same, plus a short notice "Breccia was already running"; (b) add a folder argument now (`breccia.exe
  <folder>` switches the running window to that folder), which is a new feature for a later plan. Cost if wrong: the
  callback of one plugin.
- **Q4. Where "Open log folder" goes and what it says** (M9). *Decided 2026-11-10: alternative (a), its own section "Troubleshooting" at the end of Settings.* *Recommended:* in Settings >
  About, a last row "Log files" with a button "Open log folder", which opens the folder in Explorer. *Alternatives:*
  (a) its own Settings section "Troubleshooting" at the end; (b) a link in the F1 overlay. Cost if wrong: a few lines
  of markup and step 126.
- **Q5. How much log Breccia keeps** (M9). *Decided 2026-11-10: the recommendation.* *Recommended:* two files of at most 1 MB each
  (`breccia.log` and the previous one, `breccia.1.log`), so at most 2 MB; no deletion by age. *Alternatives:* (a) two
  files of 5 MB; (b) five files of 1 MB. Cost if wrong: two constants.
- **Q6. What the log may contain** (M9). *Decided 2026-11-10: the recommendation.* *Recommended:* file and folder paths (they are what a
  bug report needs), never note text, file contents, search text or credentials; a URL's `user:password@` part is
  masked. *Alternatives:* (a) paths only relative to the notes folder (the two core messages and the watcher message
  change); (b) no paths at all. Cost if wrong: the redaction function and three messages.
- **Q7. Where people report a security problem** (`SECURITY.md`). *Decided 2026-11-10: the recommendation.* *Recommended:* GitHub's
  private vulnerability reporting (the owner turns it on in the repository's Settings > Code security), with no
  promised response time; only the latest release gets fixes. *Alternatives:* (a) the e-mail address in `CLAUDE.md`;
  (b) both. Cost if wrong: one paragraph.
- **Q8. Outside contributions** (`CONTRIBUTING.md`). *Decided 2026-11-10: the recommendation.* *Recommended:* issues are welcome; a pull
  request is welcome after its issue is agreed; the commit rules of `CLAUDE.md` apply; contributions are under the
  MIT License. *Alternatives:* (a) issues only for now, no outside pull requests; (b) pull requests welcome without
  an issue first. Cost if wrong: one paragraph.
- **Q9. Dependabot's rhythm** (M54). *Decided 2026-11-10: alternative (b), monthly, with the recommended grouping.* *Recommended:* weekly; per ecosystem one grouped pull
  request for minor and patch updates, and major updates one per pull request. *Alternatives:* (a) everything per
  ecosystem in one group, majors included; (b) monthly. Cost if wrong: the groups in one YAML file.

## Global Constraints

- The rules in `docs/audit/2026-11-10/notes.md` are invariants. In particular: nothing is emitted while the session
  lock is held; commands, the watcher callback and the index loop run off the main thread; a failed save never fails
  a command and unsaved edits win over the disk; the event payload keeps the answer's field order
  (`page_changed_payload_keeps_the_answer_field_order` stays green); the close stays bounded (`finish_close`); test
  hooks are environment variables read in one place each, with a small pure function and a test; the capabilities in
  `app/src-tauri/capabilities/default.json` are not widened (new shell calls are Rust commands).
- Spec §2: no text the user wrote is dropped, reordered or reformatted, including `breccia/config.toml`.
- Every test fails first (RED) and the RED run is recorded in the task report. A test that pins behaviour which
  already holds is shown to fail by a temporary mutation, noted in the report and reverted.
- e2e: new steps 126 (Task 6) and 127 (Task 8), placed after step 125 and before step 45. Steps assert the visible
  result and, where a file changes, the bytes on disk; they wait for states, never sleep. Expected count after the
  plan: 189 PASS lines (186 + two step lines + one `expectFile` line in step 127). The counted number is the rule.
- Commits: conventional subjects, one change per commit; `feat`/`fix` only for what a user sees, in plain words with
  no code names, paths, audit keys or task numbers, at most about 90 characters, no trailing period. No attribution
  lines. Commit on `main` and push after each commit.
- `docs/review.md`: new heading `## Safety net (plan 6)`, items 70 to 75, each added in the task named below.
- Tool versions stay fixed as in the release workflow: Rust 1.90.0, Node 24, just 1.58.0, git-cliff 2.14.2.
- No new frontend dependency. New Rust dependencies: `log = "0.4"` (core and shell) and
  `tauri-plugin-single-instance = "2"` (shell).

## Review Focus

- **A panic while a page has unsaved edits.** Recovery must not reload and drop them (Q2). Pinned in Task 7
  (`recover_keeps_a_session_with_unsaved_pages`).
- **A panic on the Git thread or the watcher, not in a command.** No command answer exists to carry the news; the
  event must, and the next command must not fail with "the session lock is poisoned". Pinned in Task 7
  (`a_lock_poisoned_elsewhere_is_recovered_on_the_next_take`) and Task 8 (`Recovery` handles an event with no
  failed command).
- **Commands already queued behind the one that panicked.** They go out with the old generation and come back
  `stale`; the user must see one notice, not one per command, and typed text that did not save must still become
  its copyable notice. Pinned in Task 8 (`quiet` tests: `stale` is quiet only for non-typing commands during the
  reload).
- **Note text reaching the log.** Panic messages quote strings; Git and URL errors can carry `user:token@`. Pinned in
  Task 5 (`panic_line_drops_quoted_text`, `redact_masks_url_credentials`) and Task 8 (step 127 checks that the
  searched text is not in the log file).
- **A second start beside `just e2e` or `just dev`.** Both must keep running beside an installed Breccia. Pinned in
  Task 9 (`single_instance_is_skipped_under_a_config_dir`); the e2e run beside a running installed Breccia is review
  item 75.

    and `Recovered` is returned without running `f` (its request belongs to the old state). Otherwise `f` runs inside

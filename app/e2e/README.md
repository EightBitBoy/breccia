Smoke test: `just e2e` (builds the release exe, starts it on a temp notes folder with the WebView2 DevTools port 9222, drives it with playwright-core and checks the Markdown on disk).
It uses the release exe rather than `tauri dev` because that starts fast and reliably, with no dev server or debug compile to wait for. Run `npm install` in `app/` first; set `BRECCIA_EXE` to test another binary. It prints one `PASS` line per step and exits non-zero on failure; port 9222 must be free.
Steps 18-24 cover the journal feed: order, hidden blank days, editing across days, virtualisation, the day title link and external changes. Steps 11-17 cover link and tag autocomplete, tree navigation, editing in a linked reference, rename from the tree menu, an external-edit conflict (Keep mine) and a new page. The app gets a fresh temp config dir through `BRECCIA_CONFIG_DIR` (settings and window state), so your own `%APPDATA%\dev.breccia.app` is never touched.
Set `BRECCIA_TRACE=1` to have the app print `trace ...` timing lines (command lock wait and run time, watcher batches) to stderr; the smoke test then prints a p50/p95 table (`trace.mjs`) before it cleans up, also on success.
The smoke test starts the app with `BRECCIA_OFFSCREEN=1`: the shell then creates the main window hidden and unfocused, moves it far off every screen and shows it without activating it (not minimised, since WebView2 may throttle a minimised window), and does not restore or save its window state. So the run neither takes the keyboard nor comes to the front; the steps drive the app over the DevTools port and need no OS focus. The `window:` line shows where the window is, and the run fails if it is not off screen or the page is not visible. A normal start ignores the switch.
As a safety net, the smoke test also remembers the front window before it starts the app and hands the front back if the app took it anyway (`foreground.mjs`); its `foreground:` line says what it did, normally "app is not in the foreground".
`just screenshots` (`screenshots.mjs`) takes the README images `docs/images/journal.png` and `board.png` the same way: release exe, temp config dir, `BRECCIA_OFFSCREEN=1`, but on a temp copy of `docs/demo/` with the Light theme and `BRECCIA_TODAY=2026-10-29`. It sets the viewport to 1280x800, captures at CSS pixels (so the size does not depend on display scaling), and fails if any note in the copy changed. Port 9222 must be free; the images are only replaced when you run it, so commit them after a look.
